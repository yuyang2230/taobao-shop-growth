# Phase 3 · AI 批量自动化（双通道）

> 目标：把"逐件改标题/补属性"从人肉 10 分钟/件压到接近无人值守。三条通道按可靠度排序，**优先级：商品管家 > 浏览器 Agent 双通道 > 纯人工**。

## 通道一：千牛「商品管家」（官方 AI，首选）

商品列表页右侧的 AI「商品管家」面板，支持对话式批量操作：

`修改商品标题 / 修改商品导购标题 / 定时上架 / 修改发货时间 / 商品上下架 / 商品ID查询 / 商品巡检 / 商品搜索`

- 官方接口直连：**不会点错行、不会断连**，一次改一批
- 用法：打开商品列表 → 商品管家 → 点对应能力 → 给它商品清单和规则（或直接贴新标题列表）
- ⚠️ 该面板随千牛版本迭代（旧版会停服升级），以你当前版本实际能力为准
- ⚠️ 批量≠免检：改完抽检 2~3 件前台展示，确认无误再放心

**它做不了的**（编辑页内多字段操作、属性面板逐项补全等）走通道二。

## 通道二：浏览器 Agent + 视觉复核（双通道架构）

任何"浏览器操作 Agent"（page-agent 类扩展、browser-use、computer-use 类工具）都适用同一个架构：

| 通道 | 分工 | 原则 |
|------|------|------|
| **Agent（动作）** | 点击、打字、按键、开标签页 | 只派**单一动作**任务；它的"完成"不可信 |
| **视觉/元素读取（复核）** | 截图、放大、读元素树 | 每一步之后**必复核**；一切以截图为准 |

**黄金法则**：
1. 单动作派发：一次只让它做一件事（按一次 Esc / 输入一段文字 / 点一个按钮）。多步任务成功率随步数骤降（实测 4 步以内可靠，8 步约 50% 失败）
2. 打字类任务耗时 1~2 分钟属正常，轮询任务状态到空闲，再复核
3. Agent 谎报成功是常态，"它说改好了"= 还没改好，必须亲眼确认

### 可靠 Agent 指令三句话（批量改标题/属性的关键，实测 2/2 成功）

凡是让打字类 Agent 做写操作，把下面三句话写进任务指令，成功率从"偶发谎报"变成可复现：

1. **"设置完成后再读取一次实际值做自我校验；如果读回值不等于目标文字，重试一次后再读"**——缺这句话时 Agent 倾向于打字未生效也报成功（同一场实测：带校验句 2/2 写入成功，不带的那次谎报"已写入"而截图仍是旧值）。无论它怎么自报，**提交前仍要截图核对字段**。
2. **"整体赋值输入框，不要用 Ctrl+A / 键盘快捷键"**——打字类 Agent 普遍不支持快捷键组合，指令里写"Ctrl+A 全选"它会停下拒绝执行。
3. **"一口气完成，中途不要停下来询问确认"**——否则它定位完输入框就停下来等人点确认。

### 已验证的页面知识（千牛 v2 编辑器，通用）

**首选工作入口：商品质量分页**（`myseller.taobao.com → 商品 → 商品质量分`），实测比"我的商品"列表好用：
- 覆盖全店商品（含非在售状态），带"商品标题/商品ID"筛选 + 质量分列，一屏看清谁有问题
- 每行的「编辑商品 / 立即优化」是**平台自带的直达链接**，点击直接打开 v2 编辑器（自带类目上下文，不会报"类目为空"）
- 筛选定位：点标题输入框 → Ctrl+A 全选 → 输入关键词 → 点搜索。**用独特关键词**（品名词/型号词），别用宽泛词；商品ID框支持多ID逗号分隔
- **定位优先用"商品ID"框而非标题框**：标题框可能残留上次的关键词，与ID条件叠加出 0 结果；ID 筛选干净，批量任务直接贴 ID 清单

其他已验证规则：
- **定位商品永远用关键词/ID搜索**，不要"找第 N 行点编辑"——行序会变、Agent 会点错行
- 编辑页顶部标签顺序会记忆上次停留位置（常落在"图文描述"），**进页先点回"基本信息"**
- 首次打开弹"商品发布提示"浮层 → 按一次 Esc 关闭
- 提交按钮在页面底部；成功页 URL 含 `success.htm`，认准"商品提交成功"字样 + 检测结果
- 必填属性为空会被拦下并自动滚到字段处，补上重提即可，已填内容不丢

### 单件商品 SOP（CUA 直操版，实测约 3 分钟/件）

用支持视觉+坐标操作的工具（computer-use 类）**全程直操**，比"浏览器 Agent 打字"快 3 倍以上（后者打一条标题要 1.5~2 分钟）：

```
1. 质量分页筛选框输入品名词 → 搜索 → 确认唯一命中行
2. 点该行"编辑商品/立即优化" → 等编辑页加载 → 切"基本信息"标签
3. 读真实标题/类目/SKU 验明身份（台账记录可能是错的，名称和ID都会串）
4. 点标题框 → Ctrl+A → 输入新标题 → 新截图核对字数计数器（55~58字节）
5. 导购标题为空就顺手补（≤15汉字）；"优化建议"红色错误=必填属性缺失，补齐（如额定电压220/驱动方式电动）
6. 点"提交宝贝信息" → 新截图确认"商品提交成功" → 写回台账 → 下一件
```

⚠️ **复核铁律**：动作之后 zoom/截图必须基于**新拍的画面**。zoom 默认裁剪的是上一次返回的帧，动作后直接 zoom 看到的是旧画面——这是最容易踩的坑，每件商品至少一次完整截图核对。
⚠️ **台账身份陷阱**：表格里"标题↔ID"对应关系会系统性错乱（截断、串行、记忆偏差）。实测多件商品名称与台账完全对不上（如台账"法兰垫"实为"法兰快夹"、"抽滤机头"实为"旋蒸机头"）。与预案不符时按真实品类重拟标题，不要硬套旧预案。

### 提交被拦的特殊场景：详情页失效图

症状：提交报"商品描述内容保存失败/引用图片失败"，指出某 img.alicdn.com 图片已被删除；"优化建议"出现宝贝详情错误。
- 重试提交无效（错误码每次变化，持久性故障）
- "高级编辑 → 保存并退出"**也清不掉**数据里的失效引用
- 唯一解法：人工进智能详情，hover 失效图模块点删除 → 再提交。新标题先存草稿（编辑器会自动保存），删完图提交时标题一起生效

### 判人工项（批量任务里的止损点）

| 项目 | 通道判定 |
|------|----------|
| **文本框属性**（如 SKU 材质列） | 可自动化：Agent 逐行整体赋值 + 自校验，实测扶优分 67→73 |
| **自定义下拉属性**（combobox + 选项浮层，如探头的"测量功能/量程"） | 不可自动化：选项 index 漂移必点错、浮层选项在元素树里不可见 → **判人工** |
| 详情页 FAQ 粘贴区 | 人工 |
| "问大家"/评价管理 | 人工（入口在千牛客户端，见 04） |
| 详情页失效图模块删除 | 人工（见上节） |

判定标准：**同一操作试 2 次仍失败/点错，立刻判人工、写进台账、继续下一件**，不磨。

### 多会话共用同一浏览器（多 Agent 场景）

多个自动化会话共用一个浏览器时，桥接扩展一次只服务一个会话，**对方跑任务会切/关你的标签，坐标点击会落到别人的页面**：
- 点任何东西之前**先点自己的目标标签**（标签条布局会变，每次重新截图定位，别信上一轮的坐标）
- 对方活跃期（如正在发布内容）避让，只做"点自己标签→点目标→截图"两连击
- OS 原生对话框（文件选择等）不受标签抢夺影响，是最稳的通道

### 无前台也能干活

窗口在后台时**截图会冻结（纯绿/旧帧），但元素树完好、元素点击仍有效** → 元素通道可继续操作、不必抢前台；坐标通道必须先拿到新截图才可信。

### 故障速查

| 症状 | 处理 |
|------|------|
| Agent 报"未连接/Hub 断开" | 重开桥接页重连；重连后活动标签会漂移，重新激活目标标签 |
| 任务 30 秒超时 | 大概率还在跑，轮询状态到空闲再判断 |
| 点了没反应 | 目标标签不是活动标签；或窗口最小化过（坐标全不可信，重新截图定位） |
| 编辑页"类目为空" | 用质量分页/列表页的行内链接进编辑器，不要手拼 URL |
| 助手报成功但实际没改 | 常态。截图复核，以眼见为准 |
| 截图是纯绿/旧画面 | 窗口在后台渲染冻结，元素通道照常干活；坐标操作先重新截图 |
| 截图核对读到旧图 | 截图类工具普遍缓存同名文件，每次截图换新文件名 |
| 用户本人在操作同一浏览器 | 先等/改只读模式，人机抢鼠标是事故第一来源 |
| 提交报"引用图片失败" | 详情页有失效图，人工删除该模块后再提交（见上节） |
| 搜索结果 0 件却确信商品在售 | 台账关键词本身是错的，换同义词重搜（垫/夹、抽滤/旋蒸这类近似词） |

## 通道三：定时任务（评论监控，轻读轻写）

逛逛发布后评论区是 B2B 询盘入口，靠人盯不现实：

- 建一个定时任务（如每 4 小时）扫"评/评论"面板：有新评论就**自动回复**，B2B 专业风格（确认参数、引导型号、引导下单），**自动回复里绝不留电话/微信**（合规红线；人工私聊回复除外）
- 每条自动回复记录进发布操作卡/台账，可追溯
- 边界：逛逛评论 Web 端可达；"问大家"入口在千牛客户端，定时任务够不到，判人工

## 护栏（自动化专用，叠加在 SKILL.md 黄金护栏之上）

1. **绝不碰价格/库存/SKU/运费模板**；非实物链接（补贴/赠品）永不进自动化队列
2. 每件商品看到"商品提交成功"才算完成
3. 连续 2 件失败 → 全停，记录现场，人工接管
4. 批量任务白天分批跑（每批 5~10 件），出问题可控
5. 模型配置自查：Agent 的 Base URL / Model / API Key 三者要配套（用你自己的密钥），混搭会静默失败
6. **止损即判人工**：下拉属性、FAQ 粘贴、"问大家"/评价、失效图删除，任一项试 2 次不成就转人工，别磨（判人工项清单见上文）
